# リード記録 運用設計（受注率・継続率を実測する）

> **作成日**: 2026-06-15
> **目的**: 広告計画書 §8 で「想定値」になっている **受注率・継続率・問い合わせ→商談率** を、実データで置き換えるための記録運用。
> **関連**: `google-ads-operation-plan.md` §2-3（リード品質記録）/ §8-3〜8-5（採算）

---

## 1. なぜ記録するのか（背景）

広告の採算は、次の3つの数字でほぼ決まる（§8-3）。だが現状はすべて「想定値」:

| 数値 | 現状の想定 | 実測したい |
|---|---|---|
| 問い合わせ → 商談率 | 60%（仮） | ✅ |
| 商談 → 受注率 | 10% | ✅ |
| 平均継続月数 | 6〜12か月 | ✅ |

> この3つが想定どおりか、良いか悪いかで「広告を増やすべき / 商談・継続を直すべき / 撤退」の判断が変わる。**初月の1件目から記録する**のが最重要。

---

## 2. 記録方法（Google スプレッドシート推奨）

- フォーム送信は Web3Forms 経由でメール（`<masked-email>`）に届く。**メールが届くたびに1行追加**する。
- ツールは **Google スプレッドシート**を推奨（GA4・Google広告と同じGoogleアカウントで完結、無料、共有が楽）。
- シートは2つ: ①**リード台帳**（1リード1行）②**月次サマリー**（広告費と集計）。

---

## 3. シート①: リード台帳（1リード＝1行）

フォーム項目に合わせた列構成。手入力するのは主に「ステータス」「商談日」「受注日」「月額」「解約日」「流入元」。

| 列 | 列名 | 入力元 | 例 |
|---|---|---|---|
| A | リードID | 連番（自動） | 1, 2, 3… |
| B | 受付日 | メール受信日 | 2026-07-03 |
| C | 氏名 | フォーム `お名前` | 山田 太郎 |
| D | 店舗名 | フォーム `店舗名` | ○○食品楽天市場店 |
| E | メール | フォーム `email` | info@example.com |
| F | 月商レンジ | フォーム `月商` | 100万〜300万 |
| G | 希望サービス | フォーム `ご希望のサービス` | 広告運用, 商品ページ制作 |

※ 2026-08-07: 通知メールの項目名を日本語化するため、フォームの `name` 属性を英語（`monthly_sales` 等）から日本語に変更。`email` のみWeb3FormsのReply-To自動設定のため英語のまま。
| H | **流入元** | 手入力（後述・4区分） | 広告(gclid確認) / 広告(推定) / 自然検索 / 不明 |
| I | **ステータス** | 手入力（ドロップダウン） | 無効 / 有効 / 商談化 / 受注 |
| J | 商談日 | 手入力（無料診断を実施した日） | 2026-07-05 |
| K | 受注日 | 手入力（契約日） | 2026-07-12 |
| L | 契約月額 | 手入力 | 50000 |
| M | 解約日 | 手入力（継続中は空欄） | 2027-02-01 |
| N | 経過月数 | 計算（継続中も含む現在の在籍月数） | 7 |
| O | 確定継続月数 | 計算（解約済みのみ確定値） | 7 |
| P | メモ | 手入力 | スパム / 折返し待ち 等 |

**N列（経過月数）の式** — 継続中も含む「今の在籍月数」:

```
=IF(K="", "", ROUND((IF(M="", TODAY(), M) - K) / 30, 1))
```

**O列（確定継続月数）の式** — 解約済みだけ確定値が入る:

```
=IF(M="", "", N)
```

> [!IMPORTANT]
> **平均を出すときは2つを使い分ける**。新規顧客が多い時期は N（経過月数）の平均が低く出る（まだ続いている人ばかりだから）。これは「現時点の実績」。§8-3の粗利LTVに使う「最終的な平均継続月数」は **O（確定継続月数）の平均＝解約した顧客だけ**で見る。O が十分に貯まるまでは LTV は保守的に見積もる。

### ステータスの定義（§2-3 と統一）

| ステータス | 意味 | 次に進むと |
|---|---|---|
| **無効** | スパム・誤送信・対象外（同業・求人など） | （ここで終了） |
| **有効** | 正常な問い合わせ。連絡可能 | → 商談化 |
| **商談化** | 無料店舗診断（商談）を実施した | → 受注 |
| **受注** | 契約締結 | （継続月数を計測） |

> ステータスは「最も進んだ段階」を入れる（受注したなら「受注」）。各段階の日付（商談日・受注日）も別列で残すこと。

### H列（流入元）の決め方

CPAは**Google広告経由のリードだけ**で計算する必要がある。配信中でも自然検索・直接流入は混じるため、「配信中＝全部広告」とみなすと広告成果が実態より良く見えてしまう。次の4区分で記録する:

| 区分 | 判定 |
|---|---|
| **広告(gclid確認)** | GA4でそのセッションが広告(gclidあり)経由と確認できた |
| **広告(推定)** | 確認できないが、配信期間中で広告経由の可能性が高い |
| **自然検索** | 検索・直接流入と判断できる |
| **不明** | 判別不能 |

> [!IMPORTANT]
> **受注CPA・有効問い合わせCPAの計算には「広告(gclid確認)」のみ**を使うのが正確。確認が追いつかない場合は「確認＋推定」で計算し、必ず "推定込み" と注記する。**自然検索・不明は広告CPAの分母に入れない**。

## 4. シート②: 受付月コホート集計（採算の答え合わせ）

> [!IMPORTANT]
> **「受付月」を基準にする（コホート集計）**。広告費は発生した月に出るが、受注は数週間〜数か月あとにずれる。「当月広告費 ÷ 当月受注数」で計算すると、7月の広告費で8月に取れた受注が分母から漏れ、CPAが崩れる。そこで **各リードを“受付月”に固定**し、あとで商談・受注・解約が起きたら元の受付月の行を**さかのぼって更新**する。コホートは時間とともに育っていく表になる。

毎月1行（その月に受け付けたリードのまとまり）。数えるのは **Google広告由来のみ**（gclid確認＋推定、§3参照）。

| 列 | 内容 | 算出 |
|---|---|---|
| 受付月 | 2026-07 | |
| 広告費 | その月のGoogle広告実費 | Google Adsから |
| 全問い合わせ数 | その月受付の広告由来リード総数 | 台帳から |
| 無効数 | うちステータス「無効」 | 台帳から |
| 有効問い合わせ数 | 全 − 無効（＝有効＋商談化＋受注） | 計算 |
| **有効率** | 有効問い合わせ数 ÷ 全問い合わせ数 | 計算 |
| 商談数 | ステータス「商談化」以上 | 台帳から |
| 受注数 | ステータス「受注」 | 台帳から |
| **有効→商談率** | 商談数 ÷ 有効問い合わせ数 | 計算 |
| **商談→受注率** | 受注数 ÷ 商談数 | 計算 |
| **有効問い合わせCPA** | 広告費 ÷ 有効問い合わせ数 | 計算 |
| **受注CPA** | 広告費 ÷ 受注数（受注0なら「—」） | 計算 |
| 実績粗利LTV | Σ(契約月額 × 粗利率 × 確定継続月数) ÷ 受注数 | O列が埋まってから |

> [!NOTE]
> **分母の統一**: 採算判断は **有効問い合わせ**（無効を除く）を分母にする。計画書 §8-3 の試算も「有効問い合わせ → 商談 → 受注」の3段で揃えてある。全問い合わせ数は「有効率」を出すためだけに使う。
>
> **営業の活動量**を見たい場合は、これとは別に「商談日・受注日ベース」の表（その月に何件商談したか）を作る。コホート表（採算）と活動表（営業量）は目的が違うので混ぜない。

> [!IMPORTANT]
> テスト期間（〜累計15万円/2か月）は **受注数がゼロでも正常**（§8-4）。この期間に注目するのは「有効問い合わせCPA」「有効率」「有効→商談率」の3つ。受注CPA・実績粗利LTVは件数が貯まってから意味を持つ。

---

## 5. 計画書（§8）へのフィードバック

実測値が3〜6か月たまったら、`google-ads-operation-plan.md` の想定値を**実数で置き換える**:

- §8-3「受注率10%」→ 実測値
- §8-3「問い合わせ→商談 60%（仮）」→ 実測値
- §8-3 LTV「継続6〜12か月」→ 実測の平均継続月数

> 例: 実測で受注率15%・継続12か月 なら、受注CPAは下がりLTVは上がる → 採算が黒字圏に入る可能性。逆に想定割れなら、広告増額より先に商談・オファー・継続施策の見直し（§8-5）。

---

## 6. 運用ルール（まとめ）

1. メールが届いたら**その日のうちに**台帳へ1行追加（A〜H列）
2. 対応の進捗に応じてステータス・日付を更新（I〜M列）
3. 月末にシート②へ当月分を集計
4. テスト期間は受注でなく**先行指標**（有効問い合わせCPA・有効率・有効→商談率）で判断
5. 3〜6か月後、実測値で計画書 §8 を更新
